What are the core architectural patterns, game mod features, and reusable components in this project?

What problems is it solving that might apply to other games or modding contexts?

Assistant answer
This is an analysis task, not a code-change task.
The project is a clean-room Unity mod rewrite built around event-driven state propagation and zero-allocation hot paths.
Its main architectural patterns are:
- A split between pure core logic in YardMasterSuite.Core and Unity/game adapters in YardMasterSuite
- A static, synchronous Action-based event bus using primitive or readonly-struct payloads
- Edge-triggered state publishing instead of constant polling
- Explicit lifecycle teardown to prevent static-event memory leaks
- UI preparation based on cached GUI text and pooled StringBuilders

Key implemented features are:
- GC/stutter watchdog
- Board/unboard locomotive sensing
- Cab control telemetry
- Consist topology tracking

Configuration is mostly build/deploy oriented today, not player-facing runtime settings.
Runtime persistence is intentionally minimal and mostly in-memory caching.
The UI framework is not yet built, but the project already defines clear zero-allocation UI rules.
The most reusable ideas for other games are performance-safe pub/sub, testable pure-core logic, and event-gated telemetry.
